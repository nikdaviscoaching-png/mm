# SPECIMEN CAMERA

A purpose-built iPhone camera for photographing polished rocks, agates, geodes, slabs, crystals and minerals at the highest practical
image quality: professional manual controls plus specimen-specific computational photography — **focus stacking**,
**reflection-aware lighting stacking**, and both **combined**. Personal use, not for the App Store. Fully offline: no accounts, no
analytics, no cloud, no third-party code.

## Build and install on your iPhone

Requirements: a Mac with **Xcode 16 or later**, an iPhone running **iOS 17+** (a Pro model for ProRAW / telephoto / LiDAR; the app
detects what your phone has and hides the rest), and a free Apple ID.

1. Open `SpecimenCamera.xcodeproj` in Xcode (it resolves the local package `Packages/SpecimenCore` automatically).
2. Select the **SpecimenCamera** target → *Signing & Capabilities* → tick *Automatically manage signing* → **Team: your personal team**
   (sign in under *Xcode › Settings › Accounts* with your Apple ID). The bundle id is `com.nikdaviscoaching.specimencamera`; if Xcode says it is unavailable, change it to anything unique.
3. Connect the iPhone, choose it as the run destination, enable *Developer Mode* on the phone if asked (*Settings › Privacy & Security*),
   press **Run**.
4. First launch: on the phone open *Settings › General › VPN & Device Management*, trust your developer profile, then reopen the app and
   allow Camera, Motion and Photos access. (Free-account builds expire after 7 days; just run again from Xcode.)

**Run the Release configuration on the phone** (the project's scheme already does: Product ▸ Scheme ▸ Edit Scheme ▸ Run ▸ Build Configuration = Release). A Debug build runs the stack processing 10–50× slower and hotter.

Command line (no signing) — **not run here**:

```sh
xcodebuild -project SpecimenCamera.xcodeproj -scheme SpecimenCamera -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO build
xcodebuild -project SpecimenCamera.xcodeproj -scheme SpecimenCamera -destination 'platform=iOS Simulator,name=iPhone 15 Pro' build
```

(The Simulator has no camera; use it only to check that the UI builds and launches.)

Regenerate the Xcode project from `project.yml` if you change settings: `brew install xcodegen && xcodegen`.

Run the headless algorithm tests (macOS or Linux with Swift 6):

```sh
cd Packages/SpecimenCore
swift test -c release -Xswiftc -enable-testing     # ~1 min
swift run -c release specimen-lab focus out        # writes PNGs for eyeballing (also: light, gen-focus, gen-light, bench)
```

## What it does

**Camera** — settings are pinned while a stack runs (the controls are locked and hidden); an optional shutter delay (default 2 s) removes tap shake; the screen stays on during sessions. Rear modules detected at launch and used *directly* (never the virtual multi-camera, so iOS can't switch lenses or enter
macro mode behind your back); each named by what it is ("Ultra Wide 13 mm", "Main 24 mm", "Telephoto 5× 120 mm"). Formats offered only if
the lens supports them: HEIF, maximum-quality (up to 48 MP), RAW (DNG), Apple ProRAW. Manual ISO (real values), shutter (1/8000 … ),
exposure compensation, white balance (Kelvin + tint, lock), focus (AF, tap-to-focus, AF lock, manual lens position with a broad drag
and a press-and-hold fine mode). ISO and shutter each have a one-tap AUTO (the other stays manual via a real metering loop).

**Focus assist** — GPU focus peaking (red by default, 7 colours, Off/Low/Medium/High, noise-adaptive), 2×/4×/8× inspection
magnifier you can pan (never changes the capture), zebras (95/98/100 %), histogram (Luma/RGB with clip markers), thirds/fine grid,
crosshair, level (horizon, or a bubble when the phone lies flat on a stand), live info.

**Stacks** (all captured into a project folder; the phone should be on a tripod)
* **FOCUS** — set NEAR and FAR, frame count AUTO (estimated from optics) or 5/10/15/20/30/any; the app locks lens, ISO, shutter and white
  balance, steps only the focus (with settling), aligns, builds multi-signal focus maps, fuses with multiband blending, writes one
  full-resolution image.
* **LIGHTING** — focus/exposure/WB locked; capture one frame per light position (≥2, 3–8 typical); retake/delete the last; thumbnails.
  Not HDR: a natural base frame is kept and only glare, reflections of coloured objects, washed colour and muddy areas are replaced
  from cleaner frames, with legitimate narrow polished highlights preserved. See `docs/DECISIONS.md`.
* **COMBINED** — focus series per light position (NEAR/FAR set once), hierarchical processing, one final.
* **IMPORT STACK** — from Photos (original resources, offline) or Files; Focus / Lighting / Combined; automatic grouping from capture
  times with a manual override. Originals are never modified or deleted.
* Motion warnings (Core Motion) during stacks; thermal throttling of *concurrency* (never quality); preflight storage/battery checks;
  interruptions keep every captured frame and resume.

**Output and storage** — default result: full-resolution **MAXIMUM QUALITY** JPEG (HEIF and 16-bit TIFF available), Display P3, with
stack-level EXIF/TIFF metadata written without recompression. Source frames and every intermediate are deleted **only after the final
is written, decoded and verified**; leave *Keep Stack Source Frames* off (default) and one image remains. Interrupted or failed projects
stay recoverable: at the next launch choose **RESUME PROCESSING** or **DISCARD**. Review screen: SAVE · EXPORT · COMPARE (final vs
source frames) · REPROCESS (preset, lighting base) · DISCARD.

**Library** — collections (CURRENT COLLECTION / CHANGE COLLECTION on the camera screen; new captures land in it automatically),
metadata per image, notes, FULL QUALITY export or WEB/EBAY COPY (2560 px, sRGB JPEG generated from the master; the master is untouched),
share sheet, Photos, move/delete. **Measure/scale**: manual reference calibration (accurate), LiDAR distance (rough, refused at macro
distances), scale stored with the image.

**Developer** — Settings › Developer tools › *Test pipelines* runs focus/lighting/combined pipelines on bundled synthetic datasets.

## Dependencies
None. Apple frameworks only. (An open-source stacking library was considered and rejected: the bespoke implementation is testable
headlessly and tuned to the specific failure modes of polished stones, and external code would add nothing the tests could not check.)

## Honest list of what is unimplemented or unverified
Unimplemented by design: aperture control, digital-zoom capture, generative fill, accounts/cloud/analytics, landscape UI.

Unverified (written, not run — everything below needs your first on-device session; `docs/TESTING.md` has the steps):
* Everything in `SpecimenCamera/` compiles? runs? — unknown. Highest-risk areas: Metal overlay shader, `CIRAWFilter` orientation, the
  exposure-priority loop, photo settings for each format on each lens, `RotationCoordinator` angles, Photos original-resource import.
* Core Image colour/orientation behaviour of the developer/encoder (the pipeline around it is tested with stubs).
* iPhone processing speed and thermal behaviour (desktop numbers only; see TESTING).
* The synthetic-data algorithm results (focus ≈ 30.2 dB vs ground truth, lighting 23→35 dB) say nothing yet about *your* stones. Real
  glossy specimens will be harder; the REPROCESS screen (preset, base frame) exists for that reason.
* The AUTO frame-count estimate is a model (see LIMITATIONS); check the first few stacks.
